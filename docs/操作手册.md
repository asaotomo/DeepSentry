| 初始化三种模式 | 首次 `--init` 可选择本地、远程 1 台、远程多台 Fleet |
| Shell-first 执行 | 默认优先用目标机原生 Shell；内置工具用于 Shell 不够稳、需要结构化解析或控制端探测的场景 |
| 多目标 Subagent | 对 `targets[]` 批量任务时，每台服务器使用独立连接上下文，避免串目标 |
| 分层长上下文 | 固定保留原始目标、最新用户修正、上一版摘要、核心线索与最近步骤；摘要失败也能继续 |

| TUI 斜杠命令 | 支持会话、Memory、Skills、MCP、TSecBench、配置和状态管理 |

| Emoji/表格对齐 | 按完整字素簇计算宽度，修复组合 Emoji 与文字重叠、Markdown 表格和询问框右边线错位 |

## 1. 快速开始

### 1.1 安装与编译

```bash
git clone https://github.com/asaotomo/DeepSentry.git
cd DeepSentry
go build -trimpath -buildvcs=false -o deepsentry ./cmd
# Windows PowerShell 可将输出名改为 deepsentry.exe
```

### 1.2 首次运行（配置向导）

```bash
./deepsentry --init
```

向导会询问模型/API 的实际上下文长度，可选自动、64K、128K、256K、512K、1M、2M 或自定义。自定义范围为 4096-4194304 tokens。请以 API 实际限制或本地服务的 `num_ctx` / `max_model_len` 为准；不确定时选“自动”。

向导会引导你配置：

| 步骤 | 说明 |
|------|------|
| AI 服务商 | DeepSeek / 智谱 GLM / MiniMax / Xiaomi MiMo / Qwen / 千帆 Coding Plan / 火山方舟 Coding Plan / 电信星辰 / 腾讯混元 / OpenAI / Claude / Gemini / Ollama 等 |
| API 地址 | 支持只填 `/v1`，自动补全 `chat/completions` |
| 模型名称 | 默认 `deepseek-flash`；也支持 `gpt-6-astra`（ChatGPT 6）、`grok-4.7`、`glm-5.3-flash`、`MiniMax-M3`、`mimo-v2.6-pro`、`gpt-5.6`、`claude-opus-5`、`claude-sonnet-5`、`gemini-3.8-flash`、`qwen3.8-max`、`hy4-preview` 等 |
| API Key | 本地 Ollama 可留空 |
| 最大轮数 | 默认 30，防止 Agent 死循环 |
| 管理模式 | 默认本地；Windows cmd 方向键无效时可用 Tab / Shift+Tab 切换 |
| 连接信息 | 根据模式录入 SSH/Telnet/FTP 或多台 `targets[]` |

配置保存至 `./config.yaml` 或 `~/.deepsentry/config.yaml`。

**管理模式说明：**

| 模式 | 结果 |
|------|------|
| 本地任务 | 清空远程连接字段，所有工具在控制端本机执行 |
| 远程管理 1 台服务器 | 写入旧版兼容字段：`target_protocol`、`ssh_*`、`telnet_*`、`ftp_*` |
| 远程管理多台服务器 | 写入 `targets[]`，主进程保持本地控制端模式，由 Fleet/subagent 逐台连接 |

### 1.3 推荐：TUI 模式

```bash
./deepsentry --tui
./deepsentry --tui "排查目标机内存与监听端口"
./deepsentry --plan "配置每 10 分钟 CPU 监控并通知"
./deepsentry --tui -c /path/to/config.yaml --resume session_xxx
```

```
┌─ DeepSentry Agent │ deepseek / deepseek-v4-flash-vision-exp ─┐

```

| 按键 | 功能 |
|------|------|
| `↑` / `↓` / `j` / `k` | 滚动 Agent 活动日志 |
| `PgUp` / `PgDown` | 翻页 |
| `Ctrl+Home` / `g` | 跳到当前保留记录的顶部 |
| `Ctrl+End` / `G` | 跳到底部并恢复自动跟随 |
| `Tab` | 聚焦底部输入框 |
| `Enter` | 发送任务 / 后续指令；正在翻阅历史时会自动回到实时底部 |
| `Shift+Enter` / `Alt+Enter` / `Ctrl+J` | 输入换行（取决于终端是否上报） |
| `Ctrl+V` / `Ctrl+Shift+V` / macOS `⌘V` | 输入框直接粘贴：图片优先生成附件卡，无图时回退为普通文本。macOS 的 Command+V 会被终端先吃掉；仅当 DeepSentry 所在窗口处于前台时，才会把剪贴板图片贴进输入框 |
| `Ctrl+U` | 清空当前输入 |
| `Ctrl+L` | 清屏 |
| `e` | 全部展开思考、工具输出和子 Agent 结果；再次按下全部折叠 |
| `Y` | 仅批准当前这一次高风险操作 |
| `A` | 本会话内允许面板标明的同类范围 |
| `S` | 允许本次会话所有高危操作；`/new` 或切换会话后失效 |
| `N` / `Esc` | 拒绝操作 |
| `q` | 仅空闲时退出；运行中不会丢弃任务 |
| `Ctrl+C` | 运行中第一次请求停止并保存 checkpoint，再次按下强制退出 |

**会话授权：** `A` 仅记住确认面板标明的受限范围。例如连续 `edit_file` 同一文件只需批准一次；工具按“同一工具 + `action/operation/mode` + 同一主机/服务/路径”等语义复用，ID、正文和 payload 等普通参数可变化。已注册 MCP 工具没有单独的 action 字段时，以工具名本身作为操作类型，因此连续截图、抓包查询等不会退化成逐次确认；`evaluate/execute/shell/terminal/script/file_write/upload` 等任意执行或写入能力仍保守绑定完整参数。其他文件、不同 Shell 命令、不同操作类型、不同目标或密码/Token 等敏感参数变化仍会重新询问。`S` 会放行当前会话后续全部需确认操作，适合连续使用 HawkEye evaluate 等同类高危工具；JavaScript 变化不再逐次打断。授权不写入 checkpoint，新建/恢复会话或重启后清空。
**长文本粘贴：** 粘贴不超过 2 行且不超过 800 字符时，输入框直接显示原文。更长的代码/日志才收成紧凑的“粘贴文本”块，提交给 AI 的仍是完整内容。后续输入保持可见可编辑；多行/换行输入中 `↑` / `↓` 优先移动光标，到达边界后才切换历史。
**图片输入：** 输入框直接 `⌘V`（macOS）或 `Ctrl+V`，有图时添加附件卡，无图时粘贴文本；不需要先输入 `/image`。macOS 终端仍会自己处理文本粘贴；图片剪贴板不会产生终端字节，因此仅当 DeepSentry 所在窗口处于前台时，才会把系统剪贴板里的 PNG/TIFF 截图贴成附件。空粘贴事件也会自动转用原生剪贴板读取。`/image path/to/screen.png` 仍可读取文件，`/image` 读取系统图片剪贴板。支持 PNG/JPEG/GIF/WebP；单张 20 MiB、单条 8 张且合计 40 MiB。纯图片可直接发送。`vision_mode: auto` 会按精确目录为 `deepseek-flash`、`gpt-6-astra`、`grok-4.7`、`glm-5.3-flash`、`MiniMax-M3`、`mimo-v2.6-pro`、`claude-opus-5`、`qwen3.8-max` 自动开启图片输入；自定义视觉模型设为 `enabled`，纯文本模型设为 `disabled`。
**历史翻阅与输入框：** 向上滚动离开实时底部后，输入区会隐藏，日志视口会扩展；按 `Ctrl+End` / `G` 或滚回底部后恢复输入。提交新消息也会自动返回实时底部。
**中文输入法：** 位于实时底部时，真实光标锚点会跟随输入行；翻阅历史时隐藏真实输入，避免候选框或光标落到日志区域。若显示行为与此不符，请确认启动的是当前构建的同一个二进制。
**Markdown 与 Emoji：** 用户询问和最终报告使用同一套 Markdown 渲染；窄窗口中的表格会自动改为键值列表。Emoji 变体选择符、肤色和 ZWJ 组合不会被拆开计算，面板绘制前还会执行最终宽度裁剪。
**用户询问与模型格式兼容：** 模型提出问题、要求补充信息或提供选项时，TUI 会进入询问面板等待用户输入；不会把需要用户选择的内容当成最终报告。模型偶尔返回普通 Markdown 或 Shell 代码块时会按类型恢复，无法可靠恢复的残缺结构会触发重试。
**sudo 权限：** 本机 TUI 会在需要时暂停全屏，把终端交给系统 `sudo -v` 隐藏读取密码，验证完成后使用 `sudo -n` 执行原命令。验证成功、失败或取消后，程序会显式恢复备用屏幕、鼠标跟踪和全屏重绘，滚轮会继续翻阅 TUI 会话。密码不会进入输入框、日志、报告、Memory 或模型上下文。可在空闲时用 `/sudo` 主动刷新授权。Batch/WebShell 等非交互模式不会索要密码；远程目标只使用免交互 sudo，不会自动复用 SSH 密码。

### 1.4 经典 CLI 模式

```bash
./deepsentry --no-tui "分析 auth.log 中的暴力破解 IP"
./deepsentry --no-tui -c config.yaml --batch -y "自动巡检"
./deepsentry --no-tui --json --task "mem_info + port_listen 摘要"
./deepsentry --webshell --task "读取最近登录日志"
```

说明：

- 默认运行会进入 TUI；脚本、WebShell、CI 建议显式加 `--no-tui`。
- `--no-tui` 普通输出会显示 AI 思考摘要，不会把完整 JSON action 作为思考内容刷屏。显式提供 `--task`/`-q` 时按一次性非交互任务执行，不会在伪 TTY 中等待追问或风险确认；需无人值守授权时显式使用 `--batch -y`。
- `--json` 输出 JSONL 事件，适合外部程序消费。
- `--webshell` 会提交后台任务并立即返回报告/进度/状态路径：后台子进程启用 `--no-tui --batch -y`，命令 stdout/stderr 会像 fscan 一样逐行写入 `reports/webshell_progress_<timestamp>.log`，`reports/webshell_status_<timestamp>.json` 记录 PID、完成状态与退出码，完整结果仍写入报告并保留给 Agent；固定索引在 `reports/latest_webshell.txt`。
- WebShell 补充信息恢复示例：`./deepsentry --webshell --resume session_xxx --task "Webhook 是 https://..."`

交互输入时会显示**示例建议**（Tab/方向键可选取）：

- 排查目标机内存与监听端口
- 分析 SSH 登录失败记录
- 审计网络暴露面与异常连接
- 在 Web 目录狩猎 webshell

### 1.5 提高任务成功率的十条技巧

1. 任务一次写清目标、时间窗、目标设备、是否允许修改以及答案格式。
2. 默认先只读采证；根因明确后，再批准最小修改、复验和回滚点。
3. 要求所有关键结论引用执行命令、关键原始输出或 artifact 路径。
4. 华为/H3C/锐捷设备显式设置 `device_type`，先完整 `display/show`，再做过滤。
5. `projection=filtered` 表示设备过滤，`output_truncated=true` 才表示输出字节截断。
6. Fleet 任务先用 `fleet_inventory` 核对 selector，避免把正确命令发到错误目标。
7. FTP 先列目录与文件大小，再传输并校验哈希；生产环境配置 `ftp_tls_mode: explicit` 或 `implicit`，保持证书校验开启。
8. 在 `models[]` 配置至少一个能力兼容的 fallback；持续 429 时从 checkpoint 恢复，不要无限重试。
9. 比赛题使用 `--competition` 和固定交付模板，提交前运行 `competition_answer_check`。
10. 自动化使用 `--no-tui --json --task`，生产变更不要开启 `--batch -y`。

推荐任务模板：

```text
目标：<要定位的问题>
范围：<目标/路径/最近多久>
权限：先只读；如需修改，先给方案、影响和回滚步骤并等待确认
证据：保留命令、关键输出、时间戳和 artifact
交付：现象→证据→根因→处置→复验→回滚；不确定项单独列出
```

## 3. 工作模式

### 3.1 本地模式、远程单机、Fleet 多机

| 模式 | 触发条件 | 工具视角 |
|------|----------|----------|
| **本地** | 单机连接字段为空，且没有指定远程目标任务 | 所有操作在控制端本机 |
| **远程单机** | 配置 `target_protocol` + 对应 `ssh_*` / `telnet_*` / `ftp_*` | 🎯 目标机 / 💻 控制端 双视角 |
| **Fleet 多机** | 配置 `targets[]` | 主进程本地控制端，按 selector 为每台目标创建连接 |

- **目标机工具**（读 `/proc`、SFTP）：`mem_info`、`port_listen`、`process_list`、`read_file`…
- **控制端工具**（从 DeepSentry 进程发起）：`ping`、`dns_lookup`、`http_probe`、`nmap_scan`…

#### 启动时使用全局代理

```bash
./deepsentry -proxy http://127.0.0.1:8080 --task "扫描 192.168.1.0/24 的 80 端口"
./deepsentry -socks5 socks5://127.0.0.1:1080 --task "扫描 192.168.1.0/24 的常见端口"
```

- 命令行代理覆盖 `controller_proxy`，仅对当前进程生效，不修改 `config.yaml`。
- `-proxy` 和 `-socks5` 不能同时使用；地址必须包含协议和端口。
- 统一覆盖 LLM、MCP HTTP、HTTP/Web、TCP/CIDR/数据库探测、SSH/Telnet/FTP 和隔离浏览器。
- HTTP/HTTPS 代理承载原生 TCP 时使用 CONNECT；代理服务器必须允许目标端口。
- Banner/状态栏只显示协议和地址，不显示 URL 中的用户名、密码。
- 目标机上的 Shell 命令不会经过控制端代理；启用代理后应优先使用 DeepSentry 原生网络工具，避免裸 `curl/nmap/ssh` 绕过路由。

### 3.2 Fleet 多目标配置

```yaml
targets:
  - name: web-01
    protocol: ssh
    host: 10.0.0.11:22
    user: root
    password: ""
    key_path: ~/.ssh/id_ed25519
    tags: ["prod", "web"]

  - name: legacy-router
    protocol: telnet
    host: 10.0.0.2:23
    user: admin
    password: YOUR_PASSWORD
    telnet_prompt: ">"
    tags: ["legacy", "network"]

  - name: ftp-backup
    protocol: ftp
    host: 10.0.0.50:21
    user: backup
    password: YOUR_PASSWORD
    tags: ["backup"]
```

selector 支持：

| selector | 命中规则 |
|----------|----------|
| `all` | 全部目标 |
| `web-01` | 按 name |
| `10.0.0.11` | 按 host 包含 |
| `ssh` / `telnet` / `ftp` | 按协议 |
| `prod` / `legacy` | 按 tag |

### 3.3 Fleet 与 target-aware 子 Agent

| 方式 | 适合场景 | 示例 |
|------|----------|------|
| `fleet_inventory` | 查看目标清单 | “列出所有 prod 目标” |
| `fleet_exec` | SSH/Telnet 批量执行只读巡检命令 | “对 prod 执行 uptime 和 df -h” |
| `fleet_file` | SSH/Telnet/FTP 文件操作 | “读取所有目标 /var/log/auth.log 末尾 100 行” |
| `task + target_selector` | 每台机器独立分析、最后汇总 | “让 log-analyst 分析所有 prod 机器登录日志” |

`task + target_selector` 示例：

```json
{
  "action": "task",
  "task_name": "log-analyst",
  "target_selector": "prod",
  "task_prompt": "审计最近 24 小时 SSH 登录日志，列出高风险 IP 和成功登录用户"
}
```

注意：

- 每个目标会创建独立 executor，不共享全局连接，避免多机并发串目标。
- 低风险只读任务可自动并发；写入、批量修改、高风险命令需要确认。
- 已配置 targets 时不要让 Agent 裸跑 `ssh/scp/sftp root@host`；这些命令不会读取 DeepSentry 配置里的密码/私钥，请使用 `fleet_exec`、`fleet_file` 或 `target_selector`。
- FTP 目标不能执行 shell，因此 `fleet_exec` 会拒绝 FTP；请使用 `fleet_file` 做 `ls/read/download/upload`。

### 3.4 Agent 动作协议

Agent 每步输出 JSON action，支持：

| action | 用途 |
|--------|------|
| `tool` | 调用内置 Go 原生工具 |
| `execute` | Shell 命令（高风险需确认） |
| `task` | 委派子 Agent；可带 `target_selector` 分解多目标任务 |
| `load_skill` | 加载安全 Skill；也可用原生工具 `skill(name=...)` |
| `todo` | 任务规划 |
| `ask_user` | 缺少关键信息或需要用户选择时，进入询问面板并暂停等待输入 |
| `read_file` / `grep` / `ls` / `glob` / `edit_file` | 文件操作 |
| `remember` / `forget` | 跨会话记忆 |
| `finish` | 完成任务 |

### 3.5 跨会话 Memory

DeepSentry 默认内置一份 `builtin://AGENTS.md`，随单二进制一起编译，不需要额外携带文件。

可选扩展：

- `~/.deepsentry/AGENTS.md`：用户级长期偏好
- `.deepsentry/AGENTS.md`：项目级规范
- `~/.deepsentry/memory/store.json`：`remember` / `forget` 写入的结构化记忆

Memory 会自动注入 Agent 上下文；明显的 API Key、密码、Token、私钥等敏感凭证会被拒绝保存。

长期记忆按固定上下文预算注入：优先保留内置安全规则、当前目标记忆和较新的条目，超出预算的内容会明确标注省略，不会无限挤占当前任务的推理空间。

会话内另有“核心线索板”，自动提取高信号的 IP、URL、CVE、哈希、文件路径和明确结论，并保留来源供 Agent 判断是用户提供、执行证据还是推断。它随 checkpoint 保存并提供给主 Agent/子 Agent 协作，但不会自动升级为跨会话永久记忆，避免把一次性噪声长期污染 Memory。

## 4. 安全应急场景指南

### 4.1 内存 / CPU 异常

```
排查目标机内存使用，列出前 20 个进程，给出结论
```

推荐工具链：`mem_info` → `process_list` → `finish`

### 4.2 网络暴露面 / 异常连接

```
审计目标机监听端口和 established 连接，识别可疑出站
```

推荐：`port_listen` → `net_connections` → `arp_table`

可先 `load_skill network-recon`。

### 4.3 日志取证

```
分析 /var/log/auth.log 中 Failed password，统计 Top 攻击 IP
```

推荐：`load_skill log-analysis` → `read_log` / `grep` → `finish`

### 4.4 Webshell 狩猎

```
在 /var/www 目录查找可疑 PHP 文件（eval/base64_decode）
```

推荐：`load_skill webshell-hunt` → `glob` + `file_strings` + `file_ident`

### 4.5 漏洞 / 基线核查

```
检查空口令账户、SUID 文件、crontab 后门
```

推荐：`load_skill vuln-scan` → 委派 `vuln-scanner` 子 Agent

服务器或办公终端需要“排查并加固”时，分别委派 `server-baseline-hardener` 或 `endpoint-baseline-hardener`，并在 `task_prompt` 写明目标、适用基线、允许的变更范围和维护窗口。未指定具体基线时，子 Agent 会记录检查依据，不宣称通过某项合规标准；加固前会核对现状和回滚条件。

### 4.6 本地 + 远程联动

```
从控制端 http_probe 探测目标 80 端口，同时在目标机 port_listen 核对
```

| `webshell-hunt` | Webshell 狩猎 |

| `awd-plus` | 多服务态势运营、证据链和处置队列 |
| `bilibili-play` | HawkEye 真实浏览器播放 B 站：搜索/`?p=N`、倍速 `playbackRate`、`press_key F` 全屏、GPU 黑屏时 canvas 抓帧 |

同一工具与参数连续重复会被循环守卫在执行前拦截（普通调用允许一次有界重试；`pwd`/`browser_tabs new` 等无效探测第二次即拦；只读快照第三次才拦）。已加载 `bilibili-play` 时禁止新开空白标签；已加载 `zipcracker` 时禁止无路径 `pwd`/`ls`。连续 3 次空转会强制结束。多步任务长时间不更新 `todo` 会被提醒。

外部 Skill 默认从 `./skills` 和 `~/.deepsentry/skills` 加载。每个 Skill 使用独立目录，且目录内必须包含带 YAML frontmatter 的 `SKILL.md`。

常用命令：

```text
/skill list

/skill unpin skill-name

```

如果当前发现了多个 Skill，只想启用 `fofamap`，直接输入：

```text

```

该命令会自动打开全局 Skill 开关、启用 `fofamap`、禁用其余当前已发现的 Skill，并立即应用到当前会话和持久化配置；不需要先执行 `/skill on`。执行 `/skill list` 可以核对最终状态。

`.skill` 本地导入兼容 ZIP 容器与单文件 YAML frontmatter + Markdown；ZIP 中必须只有一个可确定根目录的 `SKILL.md`。导入与市场安装使用相同的静态审查、来源锁、原子替换与可恢复备份；带空格的路径可用引号包裹。

### 5.2 子 Agent（task 委派）

| 名称 | 职责 |
|------|------|
| `log-analyst` | 日志取证 |
| `vuln-scanner` | 脆弱性扫描 |
| `server-baseline-hardener` | Linux/Windows Server 基线排查、逐项加固与复验 |
| `endpoint-baseline-hardener` | Windows/macOS/Linux 工作站基线排查、逐项加固与复验 |
| `webshell-hunter` | Webshell 检测 |
| `network-analyst` | 网络流量分析 |
| `host-incident-responder` | 主机入侵应急、进程/持久化证据与最小处置 |
| `network-device-analyst` | 交换机、路由器、防火墙等网络设备 CLI 排查与基线 |
| `general-purpose` | 通用多步任务 |
| `ctf-solver` | CTF 解题与证据整理 |
| `awd-defender` | AWD 防守分析 |
| `awd-plus-operator` | AWD-plus 多服务运营 |

使用：`{"action":"task","task_name":"network-analyst","task_prompt":"..."}`

示例：`{"action":"task","task_name":"server-baseline-hardener","task_prompt":"检查 prod-web-01 的账户、SSH、防火墙和审计日志；按公司基线修复已确认问题，保留回滚步骤并复验","target_selector":"prod-web-01"}`。只排查时在任务中明确“只读，不执行加固”；终端使用 `endpoint-baseline-hardener`，并写明设备及用户影响约束。

并行委派只适合相互独立的方向。运行器会自动去重相同任务、限制总体并发；每个子 Agent 收到主目标、TODO 和核心线索，并在后续步骤读取共享线索板的新证据。子 Agent 返回“任务状态、核心结论、关键证据、冲突/不确定项、建议下一步”，主 Agent 汇总后更新 TODO。有前后依赖的工作应分两批委派，不应强行放进同一个 `parallel_tasks`。

主 Agent 负责目标范围、跨角色证据合并、变更决策和最终报告。日志、主机流量、Webshell、主机应急、服务器/终端基线和网络设备各有专职角色；仅在没有对应角色时使用 `general-purpose`。网络设备子 Agent 使用厂商 CLI 和专用工具，不套用 Linux Shell 命令。

子 Agent 在父会话目录下保存独立 checkpoint，记录内部历史、已完成步骤和工具调用边界。父会话会先登记本轮子任务，再启动其动作，因此子任务运行中程序异常退出也能从父会话找到它。`--resume` 或同一 TUI 会话输入“继续”时，主 Agent 会先恢复本轮未完成子任务，再继续自己的下一轮；明确输入新任务时不会自动恢复旧子任务，即使随后重启程序也不会误接旧任务。工具执行中断且副作用不明时，恢复后先只读核验实际状态，不自动重放该动作。并行子任务的结果会先一起写入父 checkpoint，再清理已完成的子快照。

### 5.3 长上下文、核心线索与并发协作

#### 长上下文如何工作

DeepSentry 会自动管理历史，不需要用户手动复制前情：

| 层级 | 保留内容 |
|------|----------|
| 固定层 | 第一条真实用户目标、最新用户补充/修正、当前核心线索 |
| 摘要层 | 早期命令、关键输出、文件变更、失败原因、TODO、冲突和下一步 |
| 近期层 | `compact` / `balanced` / `full` 默认保留 8 / 12 / 24 条原文，巨大消息仍服从 token 预算 |
| 长期层 | `AGENTS.md` 和 `remember` 保存的跨会话规则/事实，按模型 profile 预算注入 |

当前版本按 `context_window_tokens × context_utilization - system prompt - 本轮工具 schema - 输出预留` 计算历史预算，不再使用固定 60,000 字节阈值。1M 窗口可继续积累大量有效历史；小窗口则更早压缩。摘要会覆盖所有早期分块，大段工具输出不再只保留首尾。

如果摘要模型失败、超时或被停止：

- 保留第一条用户目标和最新修正；
- 保留上一版成功摘要；
- 保留核心线索板；
- 在当前 token 预算内保留尽可能多的最近消息；
- 不会把失败的半成品摘要写回 checkpoint。

本地模型建议在 `config.yaml` 显式填写服务端实际窗口：

```yaml
model_profile: auto
model_parameter_b: 14          # 模型名已含 14b 时可留 0
context_window_tokens: 32768   # 对齐 Ollama num_ctx / vLLM max_model_len
context_utilization: 0         # 0=按 profile 自动
reserved_output_tokens: 0
native_tool_limit: 0
```

启动信息会显示实际 profile、context、输出预留和 Native Tool 直接数量。未声明窗口的本地服务会先按 32K 安全默认运行。

#### 核心线索板

核心线索板属于当前会话，最多保留 48 条高信号候选事实：

- IP、URL、CVE、哈希、Flag、文件路径；
- 明确标注为关键结论、证据、失败原因、冲突或高风险的短结论；
- 每条线索保留来源；同一线索来自多台目标或多个子 Agent 时会合并来源，不会被最后一次结果覆盖；
- 凭证、密码、Bearer Token、私钥等敏感内容不会进入线索板；
- 高优先级标识符会优先保留，普通结论不会无限增长。

查看或清空：

```text
/memory clues
/memory clues clear
```

`clear` 只清空当前会话线索，不会删除 `~/.deepsentry/memory/store.json`、`AGENTS.md` 或历史报告。核心线索会随 checkpoint 保存和恢复，但不会自动变成永久 Memory；需要跨会话保留时再使用 `remember`。

线索板内容是“带来源的候选事实”，不等于全部已经验证。主 Agent 会结合来源区分用户提供、工具证据和推断；跨目标线索未经当前目标复核，不应直接当作本机事实。

#### 多子 Agent 并发规则

当前调度边界：

| 类型 | 最大并发 | 说明 |
|------|---------:|------|
| 本地、彼此独立的子任务 | 4 | 日志、网络、文件等不同方向可并行 |
| 带 `target_selector` 的并行任务 | 3 | 控制远程连接和模型请求压力 |
| 并行任务内部的多目标展开 | 1 | 防止形成“外层并发 × 内层并发”的连接风暴 |

运行器还会：

- 忽略空任务，并对名称、任务内容、目标均相同的委派去重；
- 为每个子 Agent 使用独立执行历史和输出目录，避免长输出互相污染或覆盖；
- 只共享有界核心线索，不复制其他 Agent 的完整原始对话；
- 每个模型步骤前刷新共享线索板，因此运行时间较长的子 Agent 能读取同伴刚发布的证据；
- 停止任务后取消正在运行的模型/命令，排队任务不会继续启动；
- `parallel_tasks` 内任一任务带 `target_selector` 时，整体进入多目标风险确认流程。

推荐并行写法：

```json
{
  "action": "task",
  "parallel_tasks": [
    {
      "task_name": "log-analyst",
      "task_prompt": "只分析今天 auth.log：输出异常 IP、时间线和原始日志证据；完成后停止",
      "task_max_steps": 15
    },
    {
      "task_name": "network-analyst",
      "task_prompt": "只分析当前 established 连接和 DNS：输出可疑远端、PID 和证据；完成后停止",
      "task_max_steps": 12
    },
    {
      "task_name": "webshell-hunter",
      "task_prompt": "只检查 Web 根目录近期修改文件：输出路径、哈希和可疑代码证据；不得修改文件",
      "task_max_steps": 15
    }
  ]
}
```

`task_prompt` 应写清四件事：唯一范围、预期证据、禁止事项、停止条件。不要让多个子 Agent 都执行“全面扫描所有内容”，否则即使任务文本不完全相同，也会产生业务层面的重复劳动。

有依赖关系时使用两阶段流程：

1. 第一批并行完成日志、网络、文件取证；
2. 主 Agent 合并新线索、冲突与失败项并更新 TODO；
3. 第二批只针对第一批发现的 IP、路径或进程做定向复核。

#### 主 Agent 如何接收结果

并行任务结束后，主 Agent 会得到统一交接块：

- 总任务数、成功数、失败数、实际并发和去重数量；
- 每个子 Agent 的耗时、状态和限定长度的结果；
- 本轮新汇聚的核心线索及来源；
- 合并已验证事实、证据链、冲突、不确定项和失败任务的明确要求。

主 Agent 应先更新 TODO，再决定继续执行、发起第二阶段委派、询问用户或结束任务，不应把多个子 Agent 的原始长文本直接重复输出给用户。

### 5.4 外部 MCP

DeepSentry 支持 stdio 与 Streamable HTTP MCP Server。推荐使用结构化配置：

```yaml
mcp_server_configs:
  - name: fs
    type: stdio
    command: npx
    args: ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    cwd: "/tmp"
    disabled: false

  - name: docs
    type: streamable_http
    url: https://mcp.example.com/mcp
    bearer_token_env_var: MCP_DOCS_TOKEN
    enabled_tools: [search, read]
    required: false
```

常用命令：

```text
/mcp status
/mcp import ~/Library/Application Support/Claude/claude_desktop_config.json
/mcp add fs npx -y,@modelcontextprotocol/server-filesystem,/tmp
/mcp login docs
/mcp reconnect docs
/mcp resources docs
/mcp read docs docs://guide
/mcp prompts docs
/mcp prompt docs review topic=authentication
/mcp off fs
/mcp on fs
/mcp remove fs
```

远程 MCP 地址必须使用 HTTPS，localhost / 回环地址除外。Bearer Token 推荐只通过环境变量提供；OAuth 令牌只保留在当前进程，不写入配置文件。

连接状态为 `disconnected` 或 `failed` 时，`/mcp status` 会显示对应的重连命令。执行 `/mcp reconnect <server>` 会沿用原配置建立全新会话并重新发现 Tools、Resources 和 Prompts；为避免修改型操作已在服务端成功但响应丢失后被重复执行，DeepSentry 不会自动重放断线前的工具调用。OAuth Server 请改用 `/mcp login <server>` 重新授权。

MCP 工具始终保留 Server 提供的 JSON Schema。紧凑模型不会一次加载全部 schema，而会根据当前任务、刚刚成功调用的工具和服务端类型选择候选；未进入候选的工具仍可通过通用 MCP 路径调用。

连接 FofaMap v2.0.1 后，DeepSentry 会识别其 15 个工具。资产测绘先 `load_skill("fofamap")`，再走 `fofa_account/fofa_fields → fofa_rules → fofa_validate_query → fofa_search → fofa_search_next/fofa_export`。`next_cursor` 必须原样传递（也接受该字段作为 `cursor` 别名）。`fofa_export`/`nuclei_plan` 可扁平传 `query`/`targets`，DeepSentry 会包进嵌套 `request`。只有用户明确授权主动扫描时才执行 `nuclei_plan → 人工确认 → nuclei_execute`，计划生成的一次性令牌不能复用。stdio 推荐使用 FofaMap 虚拟环境 Python 与 `mcp_server.py` 的绝对路径，先运行 `fofamap init` 把 FOFA 密钥放入系统钥匙串，不要复制到 DeepSentry YAML。完整说明见 [DeepSentry × FofaMap MCP 适配](FofaMap-MCP-适配.md)。

连接 HawkEye MCP 后，DeepSentry 会识别 1.0.12 的 51 个工具。stdio 由本进程拉起的 HawkEye Server 会在 DeepSentry 退出时一起关闭；已有且仍被其他进程占用的实例只复用、不强杀。已连通时直接做用户任务，不要先检查安装或端口。页面操作为 `navigate → snapshot → 带 text+ref 的 click / select_option / press_key → diff 快照`；B 站播放先 `load_skill("bilibili-play")`，倍速用 `video.playbackRate`，全屏用 `press_key key=f`（自动 trusted）。公开检索必须带 `site:` / `filetype:` 等运算符。验证码走 `browser_captcha_assist`，不要 evaluate。抓包使用 `capture_state/start → history → inspect/request_get`；主动验证必须先检查授权 Scope；拦截使用 `enable → queue → release/drop → disable`。DeepSentry 会压缩 snapshot/click 的巨大 JSON，连接关闭时尝试清理由本连接开启的拦截、抓包和视口变更。

需要全屏/剪贴板等真实手势时，Click / Press Key 明确传 `clickMode=trusted` / `inputMode=trusted`；Chrome 走 CDP trusted input，Firefox 走 HawkEye native-input relay。当 `structuredContent.context.complete=false` 时必须把 `next_page_token` 作为 `page_token` 单独继续读取，1.0.12 拒绝数字 `cursor`。不要因为 GET 没有 body 就误判漏抓，应分别检查 method、request headers 和 request body。

HawkEye 截图等 MCP image 内容会落到 `reports/mcp-artifacts/`，校验后自动加入下一轮视觉消息；一轮返回超过 8 张或 40 MiB 时自动拆分。环境变量 `DEEPSENTRY_MCP_ARTIFACT_DIR` 可改保存目录。完整配置、能力矩阵、动作级审批和 Firefox 排障见 [DeepSentry × Hx0 HawkEye MCP 深度适配](HawkEye-MCP-深度适配.md)。

### 6.2 ZIP 口令恢复与伪加密修复

`zip_password_recover` 只处理控制端本地文件。远程归档先用 `file_download` 下载；不要在目标服务器直接爆破或解压。Agent 遇到 ZIP 解密/伪加密/打不开时，**第一步必须调用本工具**（有掩码用 `recover` 且 mask 原样传递，否则 `auto`）；禁止先 `inspect`/`pwd`/`python ZipCracker`/`unzip`。只有原生工具明确失败后才允许其他办法。默认 `action=auto` 按 [ZipCracker](https://github.com/asaotomo/ZipCracker) 顺序处理：伪加密修复 → 1～6 字节短明文 CRC32（恢复的是文件内容，不是口令）→ 内置约 6000 条弱口令字典 → 1-6 位数字。也可以分步调用：

```json
{"action":"auto","source":"/tmp/evidence.zip","extract":"true"}
{"action":"inspect","source":"/tmp/evidence.zip"}
{"action":"repair","source":"/tmp/evidence.zip","dest":"/tmp/evidence.repaired.zip"}
{"action":"crc32","source":"/tmp/evidence.zip","extract":"true"}
{"action":"recover","source":"/tmp/evidence.zip","dictionary":"6000.txt"}
{"action":"recover","source":"/tmp/evidence.zip","mask":"team?d?d?d?d","extract":"true","dest":"/tmp/evidence-unpacked"}
```

`inspect` 会原样带回 `source` 的下一步 JSON，避免只传 `action=repair` 而漏掉路径。`dictionary` 为 `builtin`、`6000.txt` 或 `password_list.txt` 时使用内置 ZipCracker 字典；也可以传字典**目录**。未指定策略的 `recover`/`auto` 也会自动使用该字典。WinZip AES 只支持字典/掩码。已知明文、`bkcrack`、png/exe/pcapng 模板 KPA、ZIP64/分卷修复尚未复刻，Agent 应如实说明而不是假装调用。

掩码单位是“字符位”：`?d` 数字、`?l` 小写字母、`?u` 大写字母、`?s` 常用符号、`??` 字面问号。字典逐行读取，不会整文件载入内存。默认最多尝试 1,200,000 次、超时 300 秒、并发为 CPU 数；可配置上限分别是 100,000,000 次、3,600 秒和 64 workers。

`repair` 不等于绕过真实加密。它只在新文件中清除中央目录和本地文件头的错误加密标志，再完整读取所有条目验证 CRC；若数据实际加密或归档损坏，会删除未通过校验的输出，源文件始终不修改。CRC32 命中写的是短文件明文。恢复后解压继续执行路径逃逸、非普通文件和解压体积限制。

## 10. 故障排查

| 现象 | 处理 |
|------|------|
| SSH 连接失败 | 检查端口（如 2222 非 22）、`-init` 重配密码 |
| LLM 429/超时 | 增大 `llm_retries`，检查 API 配额 |
| Agent 空转 | 减小任务粒度，或 `--resume` 继续 |
| 长会话频繁整理 | 检查是否持续产生超大命令输出；完整输出会卸载到 workspace，后续应按路径定向读取，不要反复整文件回灌 |
| 摘要失败提示 | Agent 会自动保留目标、上一版摘要、核心线索和最近消息继续；网络恢复后可直接继续，不必新建会话 |
| `/memory clues` 为空 | 当前尚未出现可提取的高信号标识或明确结论；这不表示任务历史丢失 |
| 子 Agent 重复劳动 | 把每个 `task_prompt` 改成互斥范围，并写清预期证据和停止条件；有依赖的任务拆成两批 |
| 并发任务看似变慢 | 多目标任务会主动降低并发，且内部目标展开限制为 1，这是为了避免 SSH/API 连接风暴 |
| 线索出现在错误目标 | 查看 `/memory clues` 的来源标签；来自其他 target 的线索必须在当前目标重新验证 |
| TUI/向导乱码或图标变方块 | Windows `cmd.exe` 和部分国产化终端会自动降级为 ASCII 图标但保留颜色；也可手动设置 `DEEPSENTRY_PLAIN=1` 或 `DEEPSENTRY_ASCII=1`。Windows Terminal/PowerShell 7 可用 `DEEPSENTRY_FANCY=1` 开启漂亮图标 |
| 白色终端下文字太浅或背景分块 | 默认 `terminal_theme: auto` 会探测背景并切换日间色板；老终端探测失败时使用 `--theme light` 或在配置中固定 `terminal_theme: light` |
| 需要纯无色输出 | 使用 `--no-color`，或设置 `NO_COLOR=1` / `DEEPSENTRY_NO_COLOR=1` |
| 向上翻阅时输入框仍覆盖日志，或回到底部后没有恢复 | 按 `Ctrl+End` / `G` 回到实时底部；确认启动的是当前构建产物。正常行为是离开底部后隐藏输入区，回到底部后恢复 |
| 中文输入法候选框或光标错位 | 先回到实时底部再输入，并确认启动的是当前构建产物；翻阅历史时真实输入应隐藏，候选框不会停留在日志区域 |
| Emoji 与文字重叠、表格或右边框错位 | 确认终端字体支持对应字符，并确认启动的是当前构建产物；不支持 Emoji 的终端可设置 `DEEPSENTRY_PLAIN=1` 降级 |
| 模型响应被错误显示为最终报告 | 需要补充信息或用户选择时应进入询问面板；若持续异常，检查模型兼容性、API 网关是否截断响应，并适当增大 `llm_timeout_sec` |
| `config_manage action=view` 提示未知动作 | 使用 `status` 查看安全配置摘要；`view/show/list/overview` 也作为兼容别名 |
| 出现 `root@host's password:` 并卡住 | 这是控制端裸 `ssh/scp/sftp` 的交互提示。按 `Ctrl+C` 中断，让 Agent 改用 `fleet_exec` / `fleet_file`；不要把目标密码输入 TUI 或拼进命令 |
| 本机 sudo 出现系统 `Password:` | DeepSentry 会暂时把终端交给 `sudo -v`。只在系统提示中输入；完成、取消或验证失败后会恢复 TUI。也可在空闲时执行 `/sudo` 预先验证 |
| 远程 sudo 报 `a password is required` | 出于凭据隔离，远程命令固定使用 `sudo -n`，不会复用 SSH 密码。请用 `visudo` 只为确有需要的命令配置最小范围 `NOPASSWD`，或改用具备权限的账号 |
| 编译后界面还是旧的 | 可能启动了旧二进制。推荐 `bash build.sh && cd build && ./deepsentry -c config.yaml`，或根目录 `go build -o deepsentry ./cmd && ./deepsentry -c config.yaml` |
| process_list 慢 | 已优化为限量读取；可调小 `limit` 参数 |
| FTP 批量命令失败 | FTP 不支持 shell，请使用 `fleet_file` 的文件动作 |
| FTP 控制连接成功但 `ls` 超时 | 这是数据通道失败而非账号认证失败。先用 `ftp_data_mode: auto`；若服务器在 NAT 后返回错误 PASV 地址，DeepSentry 会固定使用控制连接对端 IP；仍失败时检查服务端被动端口范围/防火墙，或在直连条件下使用 `active` |

## 12. 典型工作流示例

```bash
# 1. 初始化
./deepsentry --init

# 2. TUI 应急排查
./deepsentry --tui "服务器疑似被入侵，排查内存、端口、最近连接"

./deepsentry --tui --resume session_abc123
```

## 通讯工具连接

TUI 输入 `/connect` 打开扫码绑定窗口（飞书/QQ/微信/企微，钉钉可手动配置）；也可运行 `deepsentry --chat-setup -c config.yaml`。授权后发送 `/ds help` 可查看与终端一致的 Agent 仪表盘；私聊可直接发自然语言任务，也可用 `/ds run`、`/ds status`、`/ds result`、`/ds cancel`、`/ds new`。说「重启会话」会新开对话，说「切换会话」会列出近期会话并回复序号恢复。已绑定通道时启动 DeepSentry 会自动拉起聊天，未配置则不启动；退出时聊天进程一起停止。只想单独跑聊天时用 `deepsentry --chat`，停止用 `deepsentry --chat-stop`。

钉钉、企业微信自建应用、OneBot 和自有微信桥接亦可手动配置，详见 [聊天机器人接入](聊天机器人接入.md)。
