# 聊天机器人控制 DeepSentry

在 DeepSentry 全屏终端输入 `/connect`，或运行：

```sh
go build -o deepsentry ./cmd
./deepsentry --chat-setup -c config.yaml
```

浏览器自动打开“连接你的通讯工具”窗口。选平台，勾选是否允许执行任务，再扫码授权。保持进程运行；`Ctrl+C` 停止聊天服务，若从 `/connect` 进入则返回原来的终端界面。首次需要已有 DeepSentry 模型配置，使用 `--init` 创建。

绑定之后，无需每次扫码。无桌面服务器可运行：

```sh
./deepsentry --chat -c /absolute/path/config.yaml
```

已扫码绑定或在 `chat.channels` 里配好通道时，启动 DeepSentry 会自动拉起聊天进程；没有配置则不启动。聊天服务跟当前进程走：TUI 退出、`--chat-setup` 被 Ctrl+C，或关闭该二进制时，对应的 `--chat` 子进程和任务都会一起停掉，不会再摘成独立后台。若只想单独跑聊天，显式启动 `deepsentry --chat`；停止仍可用：

```sh
./deepsentry --chat-stop -c config.yaml
```

请从同一工作目录启动，或把 `chat.store`、`chat.binding_file`、工具工作目录等配置成绝对路径。绑定窗口只监听本机随机端口；链接带有随机访问凭证，不要转发该链接。远程服务器可将终端打印的窗口端口通过 SSH 本地转发到自己的浏览器。

## 扫码方式

| 平台 | 授权 | 收消息 | 控制账号 |
| --- | --- | --- | --- |
| 飞书（国内） | 官方应用注册 Device Flow；窗口显示二维码 | 官方 Go SDK WebSocket | 扫码返回的 open_id |
| QQ | 官方 create_bind_task；本地解密机器人凭据 | QQ Bot WebSocket Gateway | 扫码返回的 user_openid |
| 微信 | 微信 iLink 二维码及确认轮询 | iLink getupdates 长轮询 | 授权返回的 ilink_user_id |
| 企业微信 | 官方 AI Bot 授权弹窗 | AI Bot WebSocket | 扫码后把窗口的一次性 `/ds pair …` 指令发给机器人 |
| 钉钉 | 手动配置企业内部应用机器人 | HTTP 消息回调 | 配置的 senderStaffId 白名单 |

企业微信弹窗只返回 botid/secret，没有扫码用户 ID，所以额外需要一次配对，不能仅因有人给机器人发消息就赋予控制权限。只允许在私聊中配对，一次成功后配对码失效。关闭弹窗或重新取码后，旧会话的授权结果不再被接受。平台可能要求企业管理员授权、开放相应机器人能力或开通来源标识；`chat.wecom_source` 可设置企业微信分配的来源标识。二维码和授权结果由平台决定，不会用占位二维码代替平台返回值。

飞书需允许机器人接收消息并发送消息，订阅 `im.message.receive_v1` 长连接事件；扫码模板通常配置这些能力，若平台要求发布或审批，请在其控制台完成。QQ、微信的可用账号范围、单聊/群聊能力和消息有效期由平台决定。快速绑定默认只开放本人私聊；群聊通过手动通道明确配置。微信若要求短信/手机验证码，窗口可以输入验证码继续。当前快速绑定不支持国际 Lark。32 位（linux/386、windows/386）构建仍会产出，但飞书长连接 SDK 不可用；这些平台请改用其他通道，或使用 64 位构建连接飞书。

界面只在长连接鉴权成功（或微信首次成功拉取消息）后显示“已连接”。授权成功不等于消息权限或模型 API 已测试成功；请发送 `/ds help`，再执行一个任务完成真实联调。关闭浏览器不停止服务，断开按钮停止相应通道并取消它正在执行的任务、删除本地绑定；不删除平台机器人或撤销平台授权。

任务完成后，聊天回复只推送最终结论（手机可读短文，过长会拆成多条气泡），不推送逐步想法/命令日志；完整结论可用 `/ds result 任务ID` 分页查看。闲聊不会先回「处理中」，超过约 8 秒才会提示还在处理。

## 聊天指令

```text
/ds help
查看系统运行状态
/ds run 审计监听端口
/ds status
/ds status 任务ID
/ds result 任务ID
/ds cancel 任务ID
/ds new
重启会话
切换会话
```

`/ds help` 会返回与终端启动面板一致的 Agent 仪表盘（模型、连接、工具、MCP、步数等）。私聊中可直接发送自然语言任务（无需 `/ds` 前缀）；群聊自然语言任务仍需 `/ds` 前缀；已授权用户也可使用下述快捷控制指令。同一私聊会自动续聊（复用 checkpoint）。说「重启会话」、`/new` 或 `/ds new` 开启全新会话；说「切换会话」会列出近期会话，回复序号即可恢复。不同通道/用户/会话彼此隔离，最多同时跑 5 路任务；同一会话的后续消息会排队，不会返回「已有任务正在运行」。`/ds run` 后面的内容作为自然语言任务传入现有 Agent。每个任务是独立的 batch 子进程，沿用配置中的模型、Skills、MCP、工具启停和 local/SSH/Telnet/FTP 目标。聊天文本作为独立 argv 参数传递，不拼接 shell 命令。`chat.allow_batch` 或扫码窗口的执行授权允许该控制者下发任务。低风险操作自动执行；高危/中风险操作会在同一聊天里询问，回复 `允许本次`、`本会话同类`、`本次会话允许所有高危操作` 或 `拒绝`。建议为机器人使用单独的模型/工具/目标配置。未允许执行时仍可查询。

私聊普通文本在已授权执行时会提交任务；支持 `/steer`、`/delivery`、`/retry`、`/stop`、`/cancel`（无参数时停止本对话全部执行/排队任务）、`/new`、`/reset`、`/status`、`/result`、`/help`、`/sessions`；其他以 `/` 开头但不是 `/ds` 的消息会忽略。`/ds stop` 同样停止本对话全部执行/排队任务，`/ds cancel 任务ID` 只取消指定任务，`/ds result` 不带 ID 时取本对话最近任务的结果。群聊普通文本和机器人自身消息不会触发任务；图片/语音支持情况见下文。全服务最多同时执行 5 个任务，会话互不共用上下文。取消/超时会停止本地 Agent 进程树；已经完成的修改以及目标服务器上脱离连接运行的后台命令不会回滚。完整的受限长度任务输出保存在 `chat.store`（最多 1000 条记录，每条结果最多 24000 字节）；自动通知发送摘要，`result` 重新读取结果。聊天平台还有自己的内容/频率/回复时限，通知失败会记入服务日志，可再次查询。

用户只能查询或取消自己在同一通道、同一会话提交的任务。平台签名/令牌校验、用户与群白名单、有限消息去重、回调大小限制和任务超时均在 Agent 启动前执行。已保存任务的消息 ID 不会因平台重试而重复执行；服务重启将未完成任务标为 `interrupted`，不会自动重放。确认回复要求存在待确认操作，并以操作序号关联回复；消息去重先于确认处理，重复投递不能再次确认下一项操作。新建/切换会话只有保存成功才变更选择。非任务指令去重仅保留于进程内，24 小时失效；最多保留 10000 个事件，任务历史淘汰后相应去重记录也可能失效。

## 手动通道

把以下需要的条目放入 `chat.channels`，设置对应环境变量后重新启动。敏感内容用 `secret_env` 等字段引用环境变量名称。用户/聊天 ID 均使用带引号的字符串。空 `allowed_users` 不允许启动；群聊必须显式设置 `allowed_chats`，不支持 `*` 通配符。

### 飞书 WebSocket

```yaml
chat:
  allow_batch: true
  max_concurrent: 5
  channels:
    - name: feishu-team
      platform: feishu_ws
      app_id: cli_xxx
      secret_env: FEISHU_APP_SECRET
      allowed_users: ["ou_xxx"]
      # allowed_chats: ["oc_xxx"]
```

也支持 `platform: feishu` HTTP 事件回调，额外设置 `token_env: FEISHU_VERIFICATION_TOKEN`、`encrypt_key_env: FEISHU_ENCRYPT_KEY`；使用 v2 `im.message.receive_v1` 事件，启用 Encrypt Key 签名和加密。

### 钉钉应用机器人

```yaml
chat:
  allow_batch: true
  max_concurrent: 5
  channels:
    - name: ding-team
      platform: dingtalk
      app_id: "机器人 AppKey" # 媒体与过期后的主动回复必需
      secret_env: DING_APP_SECRET
      allowed_users: ["员工的senderStaffId"]
      # allowed_chats: ["conversationId"]
```

配置支持 HTTP 接收消息的企业内部应用机器人，接收地址为 `https://你的域名/chat/ding-team`。服务验证 timestamp/sign，回复到消息中的官方 sessionWebhook，仅允许 `https://oapi.dingtalk.com/robot/sendBySession`。这与已有 `dingtalk_webhook` 定时通知功能独立，普通单向群 Webhook 不能用来接收聊天指令。回调带有 sessionWebhookExpiredTime 时，过期回复自动转为应用机器人主动消息接口，需要 app_id/AppSecret 及相应发送权限。支持图片、文件、语音（转写）和图文混排入站；通过 downloadCode 换取临时下载地址。出站图片/文件先上传媒体再按单聊/群聊发送。平台或应用权限不支持的场景会返回错误，不会静默吞附件。

### 企业微信自建应用

```yaml
chat:
  allow_batch: true
  max_concurrent: 5
  channels:
    - name: wecom-app
      platform: wecom
      app_id: "ww你的CorpID"
      agent_id: 1000002
      secret_env: WECOM_APP_SECRET
      token_env: WECOM_CALLBACK_TOKEN
      encrypt_key_env: WECOM_ENCODING_AES_KEY
      allowed_users: ["zhangsan"]
```

配置回调 `https://你的域名/chat/wecom-app`，完成 URL 验证，并设置应用可信 IP。支持 AES 加密的文本消息和自建应用 API 回复。智能机器人长连接也可手动设置 `platform: wecom_ws`、`app_id: BotID`、`secret_env`、`allowed_users`。

### QQ OneBot 11（替代官方 QQ Bot 扫码）

```yaml
chat:
  allow_batch: true
  max_concurrent: 5
  channels:
    - name: qq-onebot
      platform: onebot
      api_url: "http://127.0.0.1:3000"
      secret_env: ONEBOT_EVENT_SECRET
      access_token_env: ONEBOT_ACCESS_TOKEN
      allowed_users: ["123456789"]
      # allowed_chats: ["987654321"]
```

OneBot 服务由用户自行部署/登录。反向 HTTP POST 到 `/chat/qq-onebot`，设置与 `ONEBOT_EVENT_SECRET` 一致的 secret，DeepSentry 检查 `X-Signature: sha1=…`。发送使用 `api_url/send_msg` 和 access_token。支持字符串及数组消息、私聊和白名单群聊，返回纯文本（关闭 CQ 码解析）。

### 自有微信桥接（替代 iLink 扫码）

```yaml
chat:
  allow_batch: true
  max_concurrent: 5
  channels:
    - name: wechat-bridge
      platform: wechat
      api_url: "http://127.0.0.1:3001/send"
      secret_env: WECHAT_INBOUND_TOKEN
      access_token_env: WECHAT_OUTBOUND_TOKEN
      allowed_users: ["wxid_operator"]
```

桥接登录由已有服务负责。入站 POST `/chat/wechat-bridge`，Header 为 `Authorization: Bearer <WECHAT_INBOUND_TOKEN>`，JSON：

```json
{"id":"unique-message-id","user_id":"wxid_operator","chat_id":"wxid_operator","text":"/ds help","group":false,"self":false,"timestamp":1789000000}
```

`timestamp` 使用当前 Unix 秒数（容忍前后五分钟）。出站 POST 到配置好的 `api_url`，Header 为 `Authorization: Bearer <WECHAT_OUTBOUND_TOKEN>`，JSON 包含 `chat_id`、`user_id`、`group`、`text`；服务需返回 2xx JSON，如 `{"code":0}`。不能通过消息指定任意回复 URL。

HTTP 回调需用自己的 HTTPS 反向代理转发到 `chat.listen`；扫码长连接模式无需反向代理。默认只监听 `127.0.0.1`，若容器部署需要其他监听地址，请明确设置。

## 可靠投递、实时进度与附件

### 投递与重试

所有聊天回复先写入 `chat.store + ".outbox"` 目录，再发送。每条记录包含分段进度，已收到成功回执的段不会在重启后再次自动发送。最终答案的通知信息也保存在任务记录中，恢复时用固定 ID 补齐尚未写入 outbox 的答案。任务本身仍不会自动重放。

- HTTP 429、5xx 采用指数退避，并尊重 `Retry-After`，最多 6 次发送尝试。其他明确业务拒绝标记为 `failed`。
- 网络写入后丢失响应、企业微信回执超时、服务在等待回执时退出，标记为 `uncertain`，不盲目自动重发。平台无法提供统一的恰好一次投递保证。
- `/delivery` 查看本对话最近回复的投递 ID、状态和分段进度；`/retry 投递ID` 使用当前消息的回复上下文重发尚未确认的部分。对 uncertain 记录先检查聊天，再决定是否重发。
- 使用 5 个发送 worker，按用户/对话保序，慢会话不会独占全部发送流程。重试前使用当前通道凭据，并再次检查接收者授权。卸载/撤销账号后不会通过旧凭据继续投递。
- 已送达记录在服务启动时清理超过 7 天的记录；失败记录保留供排查。目录及文件使用 0700/0600 权限。进度和确认提示关联原任务；任务结束、确认请求变化后不会再发送陈旧提示。

### 实时进度

聊天子进程通过独立的结构化进度文件输出公开步骤/工具状态；服务每 500ms 读取最新状态。默认至少间隔 30 秒推送，每个任务最多 3 次；QQ 最多 1 次，以节省被动回复额度。`/status` 可随时查看最新状态。通过 `chat.progress_interval_sec`、`chat.progress_max_messages` 调整；后者设为 -1 关闭自动进度推送，仍可用 `/status` 查询。

这是执行进度流，不是模型逐 token 答案流；原始模型 delta、推理文本、命令输出不会直接发送到聊天。最终答案仍只在任务结束后发送，避免把内部事件当成最终结论。

### 执行中补充指令

发送 `/steer 只检查，不做修改` 或 `/ds steer 补充条件`。文字补充会在当前任务下一次模型调用前加入 user 上下文；若补充到达时模型正在生成动作，会先读取补充，放弃尚未执行的旧动作并重新判断。已经在执行的工具不会因此强制中断，停止任务用 `/stop`。

每条补充仍有独立任务记录。当前任务读取后不会重复执行；如果任务在读取前已经结束，补充会转为正常排队续聊。普通后续消息仍按原行为排队。附件消息也作为独立后续对话处理，不在执行中直接注入。

### 图片、语音和文件

| 接入方式 | 图片 | 语音 | 文件 |
| --- | --- | --- | --- |
| 原生 QQ Bot | 下载图片附件并传入视觉模型 | 下载音频后调用配置的转写接口 | 下载附件并交给 Agent 读取/解析 |
| 微信 iLink | 支持 CDN 地址和 AES-ECB 解密 | 优先使用平台转写文本；否则下载/解密后转写 | 支持 `file_item` / 引用文件，下载解密后保存到本机 |
| 企业微信 WebSocket | 图片、图文混合消息，支持 AES-CBC 解密 | 使用平台 `voice.content` 转写文本 | 支持 `file` 消息 |
| 微信 HTTP 桥接 | `attachments` 中的 image URL | audio URL 或 transcript | `attachments` 中 `kind=file` |

每条消息最多 8 个附件，单个下载最多 20 MiB，总解密后内容最多 40 MiB。图片支持 PNG/JPEG/GIF/WebP；需要模型具备视觉能力。入站文件保存在任务存储目录旁的 `media/任务ID` 中，文本类会附带内容预览，办公文档（PDF/Word/Excel 等）会提示 Agent 使用 `document_parse`。

把本机文件发到聊天（例如「把桌面上的报告发给我」）时，Agent 调用 `chat_send_file`（`path` 为本机绝对路径）。任务结束后，微信会走 iLink CDN 上传并发送图片/文件；QQ Bot 走官方 files 接口。飞书、企业微信和钉钉也支持应用媒体上传与图片/文件发送；钉钉需配置 app_id 和机器人相关权限。单文件同样不超过 20 MiB。

附件下载：微信/企微/QQ 官方 CDN 走可走系统代理的下载通道；其他 HTTPS 公网地址仍做解析与内网拦截。桥接服务器应提供可直接访问的 HTTPS 下载链接。

原始音频转写配置：

```yaml
chat:
  transcription_url: "https://your-speech-service.example/v1/audio/transcriptions"
  transcription_key_env: "DEEPSENTRY_STT_KEY"
  transcription_model: "whisper-1"
```

接口须兼容 multipart `file` + `model` 请求，并返回 `{"text":"转写文字"}`。微信/企微已提供转写文字时无需配置此接口。原始 SILK/AMR 等格式能否转写取决于所选服务；当前不内置音频转码器。未配置服务、不支持的附件类型、下载/解密/转写失败，会明确回复原因，不会静默忽略。

HTTP 微信桥接示例（其余身份/签名字段沿用既有协议）：

```json
{"text":"解释这个文件","attachments":[{"kind":"file","url":"https://cdn.example/report.pdf","name":"report.pdf"},{"kind":"image","url":"https://cdn.example/image.png"}]}
```

本轮支持入站图片/语音/文件理解，以及微信、QQ 把本机文件发回聊天。语音合成尚未加入。

### 2026-09-12 附件链路更新

飞书回调/长连接现支持图片、文件、语音和图文消息；飞书、企业微信长连接与企业微信应用可通过 `chat_send_file` 回传图片或文件。微信 iLink、QQ 原生 Bot 的文件发送也接入持久化投递。收到文件后可以直接说“分析这份文件”，发送时可说“把生成的报告发给我”。

发送记录可通过 `/delivery` 查询，失败后用 `/retry 投递ID` 重发；任务完成不代表附件已送达。同名文件会分别保留。入站图片/文件会在排队时先下载到本地，避免微信/QQ 签名链接过期。飞书需开通消息资源及机器人消息相关权限，语音转写需另配服务。

### 自适应执行与桥接文件（后续更新）

企业微信应用现可接收图片、文件和语音。OneBot 支持图片/语音/文件消息段、CQ 格式和文件通知；文件发送要求 NapCat 兼容上传接口。如果桥接器返回本地文件路径，给该渠道设置 `media_root`，并把桥接器文件目录挂载到 DeepSentry 相同路径；或开启桥接器的 Base64 资源回传（例如 NapCat 的 `enableLocalFile2Url`）。不要将 `media_root` 指向整个文件系统。

自定义微信桥接出站协议：

```json
{"chat_id":"conversation","user_id":"user","group":false,"text":"","attachments":[{"kind":"file","name":"报告.txt","encoding":"base64","data":"aGVsbG8="}]}
```

桥接器执行媒体发送后返回 `{"media_accepted":true}`；仅支持文字的旧桥接器不会被误判为已送达文件。

主 Agent/子 Agent 默认按实际工具结果续步，不必手动猜测每个任务的步数。

### 会话高危操作授权

授权保存在聊天服务中，后续消息的新 Agent 子进程仍可沿用。`本会话同类`只匹配提示中显示的操作范围：任意代码执行仍要求同样的代码/参数；更换 JavaScript 不视为同类。`本次会话允许所有高危操作`允许当前渠道、聊天和发送者后续所有需要确认的操作。新建、切换会话、断开通道或重启服务都会撤销授权；切回历史会话也不会恢复旧授权。授权不会跨用户或渠道共享。
