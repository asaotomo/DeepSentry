# 纯终端接入与多设备每日巡检

## SSH、Linux 控制台、Windows CMD/PowerShell

```sh
./deepsentry --chat-setup-cli -c /absolute/path/config.yaml
```

Windows 使用 `deepsentry.exe --chat-setup-cli -c C:\DeepSentry\config.yaml`。不需要服务器桌面或浏览器，终端菜单支持：

- 飞书、QQ、微信扫码：显示字符二维码和官方授权链接，手机确认后回车查询；需要验证码时输入 `code:验证码`。
- 手动添加：飞书 WebSocket、QQ Bot、微信 iLink、企业微信 AI Bot、钉钉应用机器人、OneBot、微信桥接。企业微信使用平台管理后台取得的 BotID/Secret；平台管理员授权仍由平台完成。
- 密钥在真实终端中不回显，保存到受限权限的已有绑定文件；OneBot/微信桥接引用预先设置的入站/出站密钥环境变量。拒绝通过会回显的重定向输入接收密码。
- 状态列表、鉴权/连接检查和解绑。连接检查不向其他人发送测试消息；请本人从平台发 `/help`、图片或文件验证订阅和媒体权限。

退出向导会停止由它启动的聊天服务；如附着于已运行服务，退出只关闭向导。长期运行用 `--chat`。钉钉/桥接仍须配置 `chat.listen` 与平台可达的 HTTP 回调地址后重启，终端向导不会自动暴露公网端口。

## 推荐的简单流程：聊天 + HawkEye

先填 `inspection.example.yaml` 中的设备名、地址或已有 target、检查项；也可以直接在聊天提供设备清单。聊天 + 鹰眼无需填写 CSS 选择器。

在机器人中发送：

> 巡检 daily 设备的运行状态、最近一天安全和设备告警。网页用鹰眼，验证码问我；保留截图并发 Word 报告。

Agent 通过 `inspection_run action=inventory` 获取清单，沿用现有 HawkEye 登录、页面检查和截图工具。图片验证码先用 chat_send_file 提交截图，再使用 ask_user 提问；聊天服务在等待输入前先投递截图。需要验证码时，聊天服务会把下一条文字送回原任务，保留浏览器状态；不会把验证码排成新任务。`/stop`、`/new` 仍可中止等待，等待输入最多 10 分钟并受任务总超时约束。「本会话所有高危操作」不会自动回答验证码。

鹰眼是否能自动识别特定验证码由实际页面和工具能力决定；识别失败请用户输入，不承诺绕过验证码或 MFA。网页巡检结束后，直接调用 `inspection_run action=report`（不必手写 JSON 或安装 pandoc）。系统从当前或最新会话审计报告提取结论和真实截图，生成内嵌图片的 Word 和 Markdown。需要指定文件时传 `source=reports/report_*.md`。没有证据不能标为通过。

## 可选：固定检查配置

需要不依赖模型的固定采集时，使用同一份 `inspection.example.yaml` 里带 `command` / 选择器的设备段，合并进已有模型、targets 和聊天配置。`targets` 保存已有 SSH/Telnet 设备连接信息；`inspection.devices` 用 target 名称引用它们。网页设备独立配置 URL、凭据环境变量、登录选择器、登录成功标志及每一项检查的页面/区域。

网页登录使用独立无头 Chrome/Chromium，不需要桌面，也不复用个人浏览器登录态。可配置 `browser_binary` 或 `DEEPSENTRY_BROWSER_BINARY`。使用系统信任的设备证书；不会默认禁用证书校验或浏览器沙箱。

每个检查项可设置：

- `command`：SSH/Telnet 只读查询。支持 show/display/get 和限定的系统状态命令；禁止 shell 拼接、重定向或修改类命令。具体查询命令需按设备型号确认。
- `url`、`selector`、`screenshot`：同源网页区域与真实截图。`ready_selector` 应为各检查页面共有的已登录标志。
- `expect_regex`：预期状态；不匹配为告警。
- `alert_regex`：异常关键词；匹配为告警。
- `numeric_regex` 和 `max_value`：恰好一个数字捕获组及上限，例如 CPU 百分比。

未设置规则时标记 observed/待复核，不能据此认定正常。空结果、登录失败、权限错误、超时、缺失截图均计入失败；其他设备继续检查。验证码/MFA 需要单独解决登录方式，不会自动绕过或冒充已登录。

## 单次执行与每日运行

```sh
./deepsentry --inspect -c config.yaml
./deepsentry --inspect --inspect-selector tag:daily -c config.yaml
```

`selector` 支持设备名、target 名、标签和逗号列表。检查按设备并发（默认 3，上限 10），同设备检查顺序执行并复用浏览器会话。每台默认最多 180 秒，每项最多 45 秒。Ctrl+C 取消单次运行。

固定采集在聊天中使用 `inspection_run action=collect`（selector 指向完整检查配置中的设备）；然后调用 `chat_send_file` 发送 Word 报告。创建每日任务继续使用已有 `schedule_task`：kind=inspection、repeat=daily、明确 run_at/timezone 和 selector，经现有创建确认后保存；配置 inspection.devices 后，调度器会自动采用此流程。单独运行调度器：

```sh
./deepsentry --scheduler -c /absolute/path/config.yaml
```

交互式 HawkEye 流程与无人值守固定采集分开：当前验证码往返接在聊天任务上；纯调度器进程遇到交互登录条件不会假装成功，也不能自动把验证码问题发到任意账号。需要人工验证码的巡检请从聊天触发；无人工介入的固定检查可每日调度。没有提供真实设备清单和时间时，不会自动创建每天运行的生产任务。长期运行需使用 systemd/服务管理器维持进程，服务器和设备时钟应同步。

## 产物与证据

每次生成独立目录：`report.md`、`report.docx`、`manifest.json` 和原始 `.txt`/实际网页 `.png`。Word 内嵌图片，可以单独发送；Markdown 使用同目录相对图片链接，分享时保留整个目录。证据清单记录设备、检查项、时间、结果和文件 SHA256，可核验文件是否变化。

同一输出目录一次只允许一个巡检；异常崩溃遗留 `.run.lock` 时，确认无活动任务后再删除锁。已成功采集的项目维护本地基线，标记相较上次是否变化；修改检查规则或目标后不复用旧基线。失败采集不覆盖成功基线。

部分失败仍生成报告并返回非零退出码。pass 仅表示满足所配置规则，不是设备全面安全认证；日志时间范围以实际页面/命令返回为准，需要在配置时校验“过去一天”过滤条件。文本会遮蔽已配置登录秘密；截图应选择状态/告警区域，避免包含凭据或不相关个人信息。
